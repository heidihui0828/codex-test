
# 平面模型资料库

## 一、资料库用途

本目录用于存放可重复使用的建筑平面模型、室内空间布局模块和标准化设计资源。

建立本资料库的目的：

- 积累不同项目中具有复用价值的设计成果。
- 统一模型的分类、命名和存储方式。
- 方便未来项目快速检索和调用已有模型。
- 减少重复绘图，提高设计效率。
- 为后续 AI 辅助设计和自动化工作流程提供结构化资料。

## 二、目录结构

```text
Model/
├── readme.md
├── 住宅/
├── 商业/
├── 酒店餐饮/
├── 公共空间/
└── 空间模块/
```

分类说明：

- **住宅/**：公寓、住宅、别墅及其他居住空间的平面模型。
- **商业/**：办公室、零售店铺、商业空间等平面模型。
- **酒店餐饮/**：酒店客房、餐厅、咖啡馆等空间模型。
- **公共空间/**：公共建筑、共享空间及其他公共功能空间模型。
- **空间模块/**：可独立复用的厨房、卫生间、楼梯、走廊等空间模块。

以上目录按实际需要逐步创建，不必一次性全部建立。

## 三、模型命名规则

所有模型应采用清晰、统一的命名方式，避免使用“最终版”“新图纸”“文件01”等无法准确识别的名称。

建议命名格式：

`类别_空间类型_主要特征_版本号.文件格式`

示例：

- `住宅_两居室_标准户型_V01.dwg`
- `住宅_卫生间_紧凑布局_V01.pdf`
- `商业_办公室_开放式布局_V01.dwg`
- `空间模块_厨房_单排布局_V01.dwg`

模型修改后，应更新版本号或修订记录，避免不同版本混淆。

## 四、每个模型需要记录的信息

在条件允许的情况下，每个模型应记录以下信息：

| 信息项目 | 说明 |
|---|---|
| 模型编号 | 唯一的模型标识 |
| 模型名称 | 简洁、明确的名称 |
| 模型类别 | 住宅、商业、公共空间等 |
| 空间类型 | 客厅、厨房、卫生间、办公室等 |
| 主要用途 | 模型适用的设计场景 |
| 尺寸信息 | 长度、宽度、面积及单位 |
| 文件格式 | DWG、DXF、RVT、PDF 等 |
| 来源项目 | 原始模型所属项目或参考来源 |
| 版本号 | 当前模型版本 |
| 适用条件 | 使用限制、空间要求及注意事项 |
| 备注 | 其他需要说明的信息 |

没有确认的信息应标记为“待补充”，不得自行猜测尺寸或技术参数。

## 五、新项目资料入库流程

当收到新的项目图纸或模型时，按照以下流程处理：

**第一步：项目归档**

将原始图纸和模型保存在对应的项目目录中，保留完整的项目记录。

**第二步：资料筛选**

识别其中值得复用的平面布局、空间模块、构造节点或其他设计成果。

**第三步：复用性判断**

判断资料是否具有通用参考价值，并确认相关版权、授权和保密要求。

**第四步：整理模型**

在不破坏原始项目文件的前提下，整理出适合复用的模型副本或衍生文件。

**第五步：分类入库**

根据模型用途放入对应分类，使用统一的文件命名规则。

**第六步：完善说明**

补充模型编号、尺寸、用途、来源、版本和适用条件等信息。

**第七步：检查确认**

检查文件是否完整、能否正常打开，以及相关说明是否准确。

注意：并非每份项目图纸都需要进入通用模型库。项目原始档案与通用模型资料库应分别管理。

## 六、未来项目的资料调用流程

当开始一个新项目时：

1. 明确项目的空间类型、功能需求和大致尺寸。
2. 在模型资料库中检索相关模型。
3. 对比现有模型的尺寸、功能和适用条件。
4. 筛选出适合参考的模型，并记录其文件路径。
5. 根据新项目的实际需求进行调整。
6. 将最终确认具有复用价值的新成果整理回资料库。

模型库中的内容是设计参考，不代表可以不经核对直接用于新项目。使用前应检查实际尺寸、功能需求及适用规范。

## 七、支持的文件格式

根据不同设计软件和使用场景，可保存以下文件：

- **DWG**：可编辑的 CAD 图纸。
- **DXF**：用于 CAD 几何数据交换。
- **RVT**：Revit 建筑信息模型。
- **IFC**：开放式 BIM 数据交换格式。
- **SKP**：SketchUp 三维模型。
- **PDF**：图纸归档及只读参考资料。
- **PNG / JPG**：模型预览图及参考图片。

根据实际需求选择文件格式，不必为每个模型保存所有格式。

大型模型文件可根据需要采用 Git LFS 或外部文件存储，避免普通 Git 仓库体积过大。

## 八、版本与质量管理

- 保留原始项目文件，不直接覆盖原始资料。
- 尽可能统一尺寸单位，并在说明中明确标注。
- 避免重复收录相同模型。
- 模型修改后记录版本及修改内容。
- 更新已有模型前，先检查当前版本。
- 定期检查文件完整性及关联文件。
- 重要修改应通过 Git 提交记录保存变更历史。

## 九、版权与保密要求

- 仅收录具有合法存储和复用权限的资料。
- 未经授权，不得公开发布客户的保密图纸、个人信息或受限制的项目资料。
- 对外部参考资料，应尽可能记录原始来源和使用限制。
- 如需公开发布模型，应先确认相关授权和保密要求。

## 十、后续完善方向

随着模型数量增加，可以逐步增加以下能力：

- 建立统一的模型索引表。
- 为模型添加预览图片。
- 为每个模型建立独立的说明文件。
- 按空间类型、尺寸、风格和用途添加检索标签。
- 建立自动化命名检查和资料完整性检查。
- 让 AI 根据项目需求检索已有模型并提供参考建议。

**管理原则：先保证分类清楚、文件可靠、信息准确，再逐步增加自动化能力。所有新增规则都应服务于实际设计工作。**
