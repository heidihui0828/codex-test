# 设计工作共同规则

本文件是建筑设计、室内设计、景观设计、空间规划、图纸处理、模型处理、效果图生成及设计汇报等相关技能的共同执行规范。

所有相关技能在执行任务时，均应遵守本文件。若本文件与具体技能中的要求存在冲突，涉及原始底图、几何尺寸、空间结构及用户明确限制的内容时，以保护原始资料和用户明确要求为优先；如仍无法判断，应先向用户确认。

## 一、工作前思考

- 不要猜测关键需求；不确定时，先说明假设或向用户询问。
- 存在多种合理方案时，优先选择最简单、风险最低的方案。
- 如果用户要求的方法明显过于复杂，应主动指出更简单的做法。
- 不得虚构需求、文件、API、架构、数据或执行结果。
- 开始前明确任务目标、不可改变的内容及成功标准。

## 二、底图与几何锁定（最高优先级）

- 用户指定的原始 **CAD、DXF、SketchUp（SU）模型、PDF 技术图纸**或其他底图，是任务的几何与设计依据；不得用生成结果替代原始几何依据。
- **源文件 ≠ 普通参考图。源文件 = 不可修改的设计真值（Source of Truth）。**
- 将原始 CAD、DXF、SU、PDF 视为只读源文件。未经用户明确授权，不得修改、覆盖或破坏原始文件。
- 严格保留原始尺寸、比例、坐标、构图、空间关系、墙体、门窗、结构、家具及全部既有构件。
- 未经用户明确授权，禁止移动、拉伸、缩放、旋转、扭曲、重绘、补全、增删、合并、拆分或重新解释任何既有几何内容。
- 不得为了改善视觉效果、适配画幅或满足生成工具的习惯而改变原图。
- **效果图任务必须是“渲染源文件（Render the Source）”，而不是“重新设计源文件（Redesign the Source）”。**
- 视觉表现与几何准确性发生冲突时，优先保证几何准确性。
- 如果工具无法可靠保留原始几何，应明确说明限制，停止可能导致变形的处理，并提出更可靠的替代方案。
- 不得将未经核验的生成结果宣称为与原图完全一致。
- 只允许修改用户明确授权的内容；例如用户只要求调整材质、颜色、灯光、摄影机或环境时，不得改变模型几何或物件位置。

### 2.1 文件类型规则

- **CAD**：以现有 3D 几何、尺寸、零件、组件及装配关系为准；不得重新生成一个仅视觉相似的 3D 模型。
- **DXF**：以线条、曲线、多段线、图层、块、标注及图纸几何为准；不得擅自重画、拉直、简化或重新解释。
- **SU / SketchUp**：以现有模型、组件位置、比例、表面及空间关系为准；不得通过“清理”“优化”或重新建模改变几何。
- **PDF**：如果包含技术图纸、平面图、立面图、剖面图、尺寸或矢量几何，以其中明确的几何和尺寸信息为准；不得因信息不完整而自行发明缺失结构。
- 多视图或多来源信息发生冲突时，优先依据明确的尺寸、标注和结构信息，而不是凭视觉猜测。

### 2.2 高风险语义

以下词语**不得默认获得修改几何的权限**：

**优化、改进、完善、美化、增强、修正、重建、重绘、重新设计、重新解释**

如果这些词用于视觉任务，只能作用于材质、颜色、纹理、灯光、阴影、反射、摄影机、背景、环境及渲染风格，不得擅自作用于源文件几何。

### 2.3 修改例外

只有用户明确要求修改几何时，才允许修改。

修改后：
- 原始源文件必须保持不变。
- 修改结果作为派生版本处理。
- 不得覆盖或破坏原始文件。
- 必要时明确区分原始版本与修改版本。

## 三、固定项目流程与客户确认

所有室内设计项目统一使用 **9 个核心模块**，不得新增、拆分或重新编号。固定执行顺序为：

**01 → 02 → 03 → 04 → 05 → 06 → 07 → 03 → 08 → 09**

- 01：室内设计总控，负责全程项目管理、任务调度、流程和质量控制。
- 02：概念设计。
- 03：设计汇报与视频制作，在流程中出现两次。
- 04：空间规划。
- 05：材料与氛围设计。
- 06：景观设计；不适用时记录原因，不改变模块编号。
- 07：效果图与可视化。
- 08：施工图与深化。
- 09：预算估算。

### 3.1 第一次 03：概念方案确认

02 完成后，03 整理概念方案并向客户汇报。取得客户明确确认后，才能进入 04。客户要求修改时返回 02，修改后由 03 重新汇报。

### 3.2 第二次 03：完整设计确认

04、05、06、07 完成后，03 整合设计成果，完成版面、提案册、PPT、PDF及完整项目视频汇报。取得客户明确确认后，才能进入 08。客户要求修改时返回对应模块，修改后由 03 更新汇报并重新确认。

### 3.3 施工与预算

08 必须依据第二次 03 已确认的设计成果开展施工图深化。09 必须依据施工图、材料表及可核验工程量估算。若施工或预算调整影响已确认设计，必须返回对应模块；涉及客户确认内容变更时，重新履行汇报确认。

### 3.4 确认与记录

- 客户未明确确认，不得进入下一阶段；沉默、文件已发送或内部审核均不视为确认。
- 每次确认记录阶段、汇报版本、提交日期、客户意见、修改项、确认状态及确认日期。
- 确认状态使用：待确认 / 修改中 / 已确认。
- 已确认设计决策对后续模块具有约束力，未经重新确认不得擅自改变。
- 03 负责汇报内容、版面和视频编排；07 提供效果图、空间场景和动画素材。视频不得改变已确认设计。

## 四、简洁优先

- 用最少的步骤和必要的工具完成当前任务。
- 不添加用户未要求的功能、抽象、配置或扩展能力。
- 优先复用现有文件、标准工具、原生能力及已有依赖。
- 如果实现可以更简单且不影响准确性，应主动简化。

## 五、精准修改

- 只修改完成当前任务必需的内容。
- 不顺手重构、格式化、移动或清理无关文件。
- 保持现有项目结构、命名规则和文件风格。
- 仅清理因本次修改产生的无用内容。
- 修改原始图纸、模型或技能文件前，确认目标文件及修改范围；不得擅自覆盖唯一原件。
- 优先保留原始文件，并将修改结果另存为新版本；只有用户明确要求时才覆盖原件。

## 六、目标驱动与结果验证

- 开始前明确成功标准及验收条件。
- 修复问题时，先识别并尽可能复现问题，再实施修复。
- 修改完成后，根据任务类型进行验证，包括文件读取、尺寸与比例核对、图层或构件检查、测试、格式检查或构建验证。
- 图纸和模型任务应优先对照原始文件核验几何；仅凭视觉相似，不足以证明尺寸和结构一致。
- 如果验证失败，应继续排查；无法解决时，应明确指出失败项目及其影响，不得将未验证的结果作为已完成成果提交。
- 清楚区分已执行、已验证、未验证及无法完成的事项。

## 七、默认原则

**最少假设、最简单实现、最小改动、几何优先、结果可验证。**
